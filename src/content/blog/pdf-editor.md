提出用に「表紙1ページ、本文3ページ、参考資料2ページ」をまとめるなら、完成形は6ページです。先にこのようなページ構成を決めておくと、結合できたのに一部が抜けていた、という失敗を見つけやすくなります。

PDFの結合は、見えているページを集める作業です。電子署名、入力フォーム、しおりなど、文書全体に付随する情報まで引き継げるとは限りません。まず原本を複製し、配布用と保存用を分けましょう。

## 結合ツールで扱う作業と、別の方法が必要な作業

| やりたいこと | 選ぶ方法と確認点 |
| --- | --- |
| 複数PDFのページを1本にする | ページ結合。総ページ数と順序を決める |
| 不要なページを除く | ページ削除。裏面や別紙まで消していないか確認 |
| 本文の誤字を直す | 原稿を修正してPDFを再作成。結合では本文を書き換えない |
| スキャン画像を検索可能にする | OCRが必要。単純な結合では文字認識されない |
| 電子署名済み文書を提出する | 原本での提出要件を確認。結合したコピーを署名原本の代用にしない |
| パスワード保護を解除する | 権限とパスワードを持つ人が対応ソフトで操作する |

GlowPunchはページ結合・並べ替え・削除のためのツールです。OCR、パスワード解除、電子署名の検証には対応していません。

## 失敗しにくい手順

1. 元のPDFをそれぞれ開き、ページ数と内容を確認する。
2. 「表紙 → 本文 → 別紙」のように順序をメモし、出力に必要な合計枚数を数える。
3. [PDF結合ツール](/tools/pdf-editor/)にファイルを読み込み、サムネイルを見て並べる。削除は必要なページを確認してから行う。
4. 別名で保存し、保存したPDFを改めて開く。プレビューが正常でも、最終出力まで正常とは限らない。
5. 総ページ数、先頭・末尾、資料の境目を確認する。提出用なら全ページを確認する。

ファイル名の並びだけを頼りにせず、各ページの見出しを確認してください。表紙だけ横向き、本文だけ余白が違う、といった混在は結合処理では自動修正されません。

## 保存後の確認表

- **文字**：検索できていた語が検索できるか。日本語や記号が欠けていないか。
- **ページ**：白紙や重複が増えていないか。縦横の向きと用紙サイズが想定どおりか。
- **フォーム・注釈**：入力値やコメントが必要な場合、保存後にも残っているか。
- **リンク・しおり**：利用する人に必要なものが機能するか。
- **機密情報**：不要な別紙や見せるべきでない注釈を含めていないか。

ページ削除は、残したページ内の個人情報を墨消しする機能ではありません。文字の上に黒い図形を重ねただけの資料も、元の文字が取り出せることがあります。正式な墨消しには対応ソフトでの確認が必要です。

## 読み込めない・保存できないとき

まず1ファイルずつ読み込み、問題が特定のPDFに限られるか調べます。パスワード付きPDF、破損ファイル、画像の多い大容量PDFは失敗の原因になります。枚数を減らして試す場合も原本を残してください。

GlowPunchは表示用のPDF.jsと編集用のpdf-libを使います。表示できることと編集できることは別です。使用している[pdf-libの制約](https://github.com/Hopding/pdf-lib#limitations)にも暗号化PDFの扱いが示されています。保護文書を無理に読み飛ばすより、作成者から編集可能な原稿を受け取る方法を選びましょう。

処理はブラウザ内で行います。資料を外部へアップロードしない一方、端末のメモリは必要です。大量のスキャンをまとめる場合は、組織で許可されたデスクトップソフトの方が適することもあります。
